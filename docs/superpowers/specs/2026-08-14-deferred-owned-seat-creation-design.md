# 自建桌面座位延迟创建设计

## 目标

宠物决定使用应用自建座位时，先走到屏幕内随机安全落点；只有首次移动完成后，才创建 `宠物的座位.tmp`。用户不应在宠物仍在路上时看到应用创建的桌面文件。

## 行为流程

1. 座位选择阶段若命中 10% 自建分支，只返回一个“待创建”虚拟目标，不执行文件系统命令。
2. 宠物使用现有屏幕边界与 30° 路径规划走到随机目标点。
3. 首次移动成功且动作未取消后，调用 `create_owned_seat_file`。
4. 最多等待 2 秒，从桌面目标提供器重新发现新文件的真实图标坐标。
5. 若取得坐标且与当前位置不同，宠物再走到真实图标；否则在当前位置显示虚拟座位标记并落座。
6. 动作结束后，已有 `FoodSafety` 流程验证所有权并将自建文件移入废纸篓。

## 取消与错误

- 首次移动被取消或失败：不创建文件。
- 创建失败：降级为当前位置的纯 UI 虚拟座位，不留下文件。
- 创建成功但坐标发现失败：使用当前位置虚拟标记，结束时仍回收应用自建文件。
- 用户原有桌面文件、文件夹和窗口始终只读。

## 测试

- 自建分支选择阶段不调用创建命令。
- 首次移动完成前不调用创建命令。
- 首次移动完成后只创建一次。
- 首次移动取消时创建次数为零。
- 真实坐标可用时允许一次后续移动；不可用时使用当前位置虚拟标记。
- 全量 TypeScript、Rust 测试和构建继续通过。
