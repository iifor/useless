# 单实例与宠物视觉尺寸设计

## 目标

- 同一用户会话中只允许运行一个 UNO 宠物实例。
- 所有普通姿势的可见长边从 `200px` 缩小到 `170px`。
- `idle-prone` 趴姿使用 `145px` 可见长边，修正其头部和横向身体造成的视觉面积偏大。
- 保持现有动态紧凑窗口、8px 透明留白、动作锚点和像素命中逻辑。

## 单实例

接入 Tauri 2 官方 `tauri-plugin-single-instance`，并按官方要求在插件链最前面初始化。第二次启动时不创建新宠物，只显示并聚焦已经运行的主窗口。

现有 `instance_position` 继续负责首次实例的屏幕内初始位置；不再依靠它为多个进程分配不同位置。已经运行的旧版本进程无法由新二进制安全接管，安装或调试新构建前需要手工退出旧实例一次。

## 尺寸计算

运行时继续分析每个动画全部帧的 alpha 联合边界，并让同一动画共用一个缩放值：

- 默认目标长边：`170px`。
- `idle-prone` 目标长边：`145px`。
- 其他姿势不增加独立特例。
- Canvas 和原生窗口继续由缩放后的联合边界加四周 `8px` 得出。

菜单、文件确认框、桌面目标图标和交互窗口 `280×320` 不参与宠物人物缩放。

## 错误处理

- 第二实例通知失败时不影响现有实例继续运行。
- 主窗口暂时不可见时，第二次启动尝试显示并聚焦窗口；调用失败只记录日志。
- 动画 alpha 分析失败时仍使用相同的姿势目标长边作为整帧回退缩放。

## 测试与验收

- TypeScript 验证默认姿势目标为 `170px`，`idle-prone` 为 `145px`，两者继续产生紧凑 viewport。
- Rust 不重复测试官方插件内部锁；通过应用启动集成和 Tauri 构建验证插件接入。
- 连续启动应用两次，桌面只出现一个宠物；第二次启动聚焦现有宠物。
- 逐项切换站、坐、走、躺、睡和趴姿，普通姿势整体缩小，趴姿视觉面积不再明显大于站姿。
- 完整前端、Rust 测试、生产构建和 Tauri debug 打包保持通过。
