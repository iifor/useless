# 打包版宠物交互与自动动作设计

## 目标

修复 `UNO-PangYu.exe` 中宠物无法左键拖动、无法右键打开菜单的问题，并确认打包版启动后默认持续执行随机自动动作。构建产物名称继续使用 `UNO-PangYu.exe` 和 `UNO-PangYu-Setup.exe`。

## 已确认的故障边界

左键拖动和右键菜单在 `PetRenderer` 中共用 `isBodyHit()` 门控。该门控会在鼠标事件发生时读取 Canvas 单个像素的 Alpha 值。用户确认打包版的两类操作同时失效，而开发环境两类操作都正常，因此共同的像素命中门控是当前能够由源码和运行现象共同支持的故障边界。此次通过移除鼠标事件对该门控的依赖来验证并修复问题；最终是否修复以新打包程序的实际操作结果为准。

自动动作调度已经存在于 `App`：程序默认进入自动模式，并在站立、坐下、直线行走和寻找座位之间随机切换。此次不另建调度系统，只补充回归测试并对最新打包产物做运行验证。

## 交互设计

### 命中规则

宠物交互改用浏览器已经完成的 Canvas 元素命中，不再在鼠标按下或右键时读取单个像素。Canvas 会根据动画内容边界紧密裁剪，并保留约 8 像素的绘制边距，因此有效交互区域仍贴近宠物，不会扩展到整个透明窗口。

左键和右键必须使用同一条命中规则：

- Canvas 收到鼠标左键按下时，启动原有窗口拖动流程。
- Canvas 收到右键菜单事件时，阻止 WebView 默认菜单并打开原有宠物菜单。
- Canvas 之外的透明窗口区域不触发宠物操作。
- 菜单或食物交互开启时，继续沿用现有的拖动禁用规则。

### 右键菜单

保留现有动作、文件和宠物能力三级入口。打开菜单时继续将窗口从紧凑模式切换为交互模式；关闭或选择动作后恢复紧凑模式。此次不改菜单内容与视觉样式。

## 自动动作设计

程序启动时保持 `automatic = true`。自动循环继续使用现有调度规则：

- 常规动作在站立、坐下和慢走之间随机切换，并避免立即重复当前动作。
- 以现有概率插入寻找座位动作。
- 所有移动继续使用当前的水平或垂直分段路径，不允许斜线移动。
- 单次动作失败时记录错误、恢复站立，短暂等待后继续循环。
- 用户在右键菜单选择手动动作时暂停自动循环；选择“自动模式”时恢复随机循环。

此次不增加动作顺序编辑、时间配置、状态持久化或新的动作种类。

## 代码范围

预计修改范围仅包括：

- `src/pet/PetRenderer.tsx`：移除鼠标交互对单像素 Alpha 检测的依赖。
- 对应宠物交互测试：覆盖左键、右键和禁用拖动规则。
- 自动动作测试：确认默认随机动作集合、寻找座位概率和直线路径约束没有回退。
- 构建测试：确认公开产物名仍为 `UNO-PangYu.exe` 与 `UNO-PangYu-Setup.exe`。

现有未提交的 `src-tauri/Cargo.toml` 与生成的 schema 文件不在本次修改范围内，必须保留原状。

## 错误处理

- `startDragging()` 失败时继续执行现有拖动结束恢复逻辑，不让自动动作永久停止。
- 窗口切换或菜单布局失败时保留现有中文控制台错误信息。
- 自动动作异常继续由现有循环捕获，不因单次失败终止自动模式。

## 验证标准

自动化验证：

- 交互测试证明左键事件会进入拖动流程。
- 交互测试证明右键事件会打开菜单并阻止默认菜单。
- 拖动禁用状态下左键不启动拖动。
- 自动动作和直线路径现有测试全部通过。
- Windows 构建测试确认产物名称不变。
- 完整前端测试、生产构建和 Rust 检查通过。

打包运行验证：

- 使用公开命令重新生成 `release/UNO-PangYu.exe` 和安装包。
- 直接运行新生成的 `UNO-PangYu.exe`。
- 左键可以拖动宠物。
- 右键可以打开宠物菜单并选择自动模式。
- 观察宠物自动切换至少两种动作，并确认行走路径没有斜线。
- 验证结束后关闭测试实例，不留下额外宠物进程。

## 非目标

- 不删除旧构建产物。
- 不重写为 Windows 原生菜单。
- 不增加动作配置界面。
- 不合并、推送或发布到远程仓库，除非用户另行要求。
