# 聚焦窗口座位优先级设计

## 目标

寻找桌面座位时严格执行以下顺序：

1. 当前聚焦且通过安全过滤的其他应用窗口。
2. 当前显示器上可用的现有桌面文件或文件夹图标。
3. 两者都不存在时，返回待创建座位；宠物抵达随机落点后才创建应用自有空文件。

移除窗口与图标的 50/50 随机分类，以及有现成目标时仍以 10% 概率自建文件的规则。

## 平台聚焦判定

- macOS：通过 `NSWorkspace` 取得前台应用 PID，再从 CoreGraphics 按前后层级排列的窗口中选择该 PID 的第一个合格窗口。
- Windows：通过 `GetForegroundWindow()` 取得当前聚焦 HWND，并与 Win32/DWM 枚举结果精确匹配。
- UNO 自身窗口、隐藏窗口、最小化窗口、透明工具窗口、Dock/任务栏、桌面容器、当前显示器之外的窗口，以及顶部空间不足的窗口都不合格。
- 前台应用存在但没有合格窗口时，视为“无合适聚焦窗口”，回退桌面图标；不得选择其他非聚焦窗口。

## 数据与选择流程

Rust 窗口原始数据增加 `focused` 标记，过滤后只把合格的聚焦窗口作为窗口座位返回。`find_seat_targets` 找到该窗口后立即返回，不触发 Finder Apple Events 或 Windows Explorer UI Automation。

没有合格聚焦窗口时，才读取并过滤桌面图标。TypeScript 选择器仍做同样的优先级保护：优先 `focused` 窗口，否则随机一个图标；候选为空时返回现有的待创建目标。

窗口落座、到达前刷新、每秒状态检查、30° 行走路径和应用自有文件回收流程保持不变。

## 错误与权限

- 聚焦窗口 API 失败：按无聚焦窗口处理，继续尝试桌面图标。
- Finder/Explorer 坐标读取失败：返回空候选，进入抵达后自建文件流程。
- 发现聚焦窗口时不读取桌面图标，避免无必要的桌面授权请求。
- 用户已有文件、文件夹和窗口始终只读。

## 测试

- TypeScript 验证聚焦窗口优先于图标、无聚焦窗口时选择图标、两者都没有时返回待创建目标。
- Rust 验证只返回聚焦且合格的窗口，UNO 自身聚焦和不合格聚焦窗口均回退。
- macOS 验证前台 PID 与 CoreGraphics 层级匹配。
- Windows 验证前台 HWND 精确匹配。
- 完整前端、Rust 测试、生产构建和 Tauri debug 打包保持通过。
